2026 年 9 月 15 日，一个**不聊天、不写代码、连一个字符都不吐**的 AI 模型刷屏了。

它叫 **Jev**，由前 OpenAI 核心研究员 Diogo Almeida 联合创立的 **TypeSafe AI** 发布。它做的事只有一件：**做判断**。给你一段状态和几个问题，它返回选项、分数或概率——不生成任何文本。

上线 36 小时，**14 万名开发者涌入内测**；接入 Vercel AI Gateway 不到 24 小时，**近 13% 的付费团队**用了它，是 GPT-5.6 系列上线首日的 2 倍；上线数周后，TypeSafe AI 估值冲到 **75 亿美元**。

一个「哑巴」模型，凭什么火成这样？这篇文章拆三件事：**它到底是什么、为什么会火、有哪些开源同类产品**。

## 1. Jev 是什么：把「嘴」缝上，只留判断

### 1.1 三种原语

Jev 不生成文本，只提供三种结构化输出：

| 原语 | 是什么 | 例子 |
|------|--------|------|
| **Choice** | 从给定选项里选一个 | 这条工单该分给哪个部门？ |
| **Score** | 按等级打分（2-10 级自定义） | 这段代码的迁移风险几分？ |
| **Noul** | 是非判断，返回 0-1 概率 | 「用户在要求退款」成立概率 0.97？ |

调用方式极简——给一段 **state**（要分析的上下文）和一组 **questions**，直接拿回带概率和置信度的结构化答案：

```json
{
  "is_urgent": {
    "type": "noul",
    "noul": 0.8
  }
}
```

**为什么这个设计很值钱？** 因为答案只能落在预先声明的选项空间里——**结构上给不出格式错误**。官方称其在结构化输出与工具调用场景的错误率为 **0%**，而前沿模型通常在 0.5% 以上。

### 1.2 名字里的两重暗示

- **System One（系统一）**：借自卡尼曼《思考，快与慢》——不假思索、凭直觉瞬间给出的判断。国内券商的比喻更形象：**给 Agent 装个小脑**。
- **Jev**：取自经济学家杰文斯（Jevons），暗合**杰文斯悖论**——智能的使用成本暴跌，智能的用量就会暴涨。

### 1.3 快、便宜，是怎么做到的

| 维度 | 传统 LLM | Jev |
|------|----------|-----|
| 输出方式 | 逐 token 生成文字，程序再解析 | 直接返回结构化决策 |
| 响应速度 | 3 – 329 秒 | **70 – 500 毫秒** |
| 定价 | 输入 + 输出都收费 | 输入 $0.042/百万 token，**输出免费** |

**快的原因**：没有逐 token 解码过程，所有输出并行采样，一次给完。**输出免费的原因**：既然不逐字生成，那就没有值得计费的输出——官方原话是「便宜到根本不值得计费」。

**准的原因**：训练方法是 **RLCD（校准决策强化学习）**。RLHF 奖励的是「人类看了很爽」，RLCD 奖励的是「**你给的概率得和你的实际命中率咬合**」——模型说 0.9，那必须有九成时候是对的。

这条性质在实战里非常有用：社区实测跑 24 封挪威听证信函，**答错的那几封恰好是置信度最低的那几封**——不确定性信号可信，就能按阈值分流（高分自动执行，低分转人工）。

### 1.4 边界：它不是万能的

- **数学推理顶多 GPT-4 水平**——它不是用来做推导的
- **不支持图像输入**（这点 OpenAI 的竞品补上了）
- **"输出免费"不等于"零成本"**——延迟、集成复杂度、置信度阈值的调参，都是要付的隐性成本

## 2. 为什么会火：三个叠加因素

### 2.1 需求端：Agent 的账单里藏着"高频小判断"

这是最关键的一层。一个 Agent 跑起来，最费钱的往往不是"生成一段漂亮的代码"，而是中间那些**细碎的小判断**：

- 这条消息是投诉还是咨询？
- 该调哪个工具？
- 这步操作有没有风险？
- 要不要重试？
- 工单派给谁？

这类判断一天发生**成千上万次**，每一次都要大模型写一段文字才能得出结论——**等于雇了个作家来做收发室的活**。

有人拿传统大模型做个智能分类路由，烧了几百上千 token 就为了拿回两三个 JSON 字段——**拿大炮打蚊子**。

Jev 把这层从大模型身上剥出来，交给一个便宜的专用层。**快的模型管快判断，慢的模型管深度推理**——这个分工对做企业应用的人来说一点都不陌生。

### 2.2 产品端：把两个痛点同时打成卖点

社区原话是「**它不是因为强，是因为它戳中了两年的憋屈**」：

> **token 费用太贵，AI 响应太慢。**

一个 Agent 完成任务，背后可能发生**几十次模型调用**。单次开销不大，但在持续运行中重复判断会明显推高整个任务的成本和耗时。Jev 官方测试：**快 193.6 倍，成本约为 1/444.6**（官方口径，且注明并非所有任务都能获得同样提升）。

### 2.3 传播端：它天生适合做 Demo

这是被低估的一环。**一个不输出文本的模型，反而特别适合拍视频**：

| Demo | 数据 |
|------|------|
| 实时打《毁灭战士》 | 每秒 10 次决策，一小时算力约 $7 |
| 《我的世界》屠末影龙 | 8 分 43 秒，131 次 Jev 决策 + 35 次 Astra 规划调用 |
| 浏览器查航班（苏黎世→伦敦） | 7.1 秒，$0.0039 |
| Mac 语音助手 | 话没说完 App 已弹出来 |
| 简历自动填表 | 姓名填姓名、邮箱填邮箱，一路 V 到底 |
| 审 1000 个 PR | 7 美分（Opus 5 同等任务需 $14.5） |

而且它自带的传播钩子极强：**「一个不会说话的 AI 火了」本身就是最好的标题**。发布当天冲上 Hacker News 千分级，36 小时 14 万人涌入内测。

### 2.4 资本层：10 天估值涨 50 倍

| 时间 | 事件 |
|------|------|
| 9/15 | TypeSafe AI 结束两年隐匿期，发布 Jev |
| 9/16 | 冲上 HN 首页，创始人 Diogo 发长炮："当年那条路，咱们走偏了" |
| 9/18 | Vercel 披露 24 小时内 13% 付费团队接入 |
| 9/21 | 全面开放，API 一度被挤宕机；用户破 100 万 |
| 10/6 | **OpenAI 三周后紧急推出竞品 Decisions API**（基于 GPT-6 Luna） |
| 10/9 | a16z 领投 8.7 亿美元，估值 75 亿美元 |

**创始人的故事**也很有说服力。Diogo Almeida 是 ChatGPT 共同发明人之一、InstructGPT 论文第四作者、RLHF 核心奠基人。2024 年 ChatGPT 爆火后他离开 OpenAI，原因是：

> 在共同发明了 ChatGPT 之后，我一直在问自己：为什么超人类的聊天模型没有带来 AGI？这么聪明的 AI，到今天还得靠人类盯着才能干活。

他的判断是 **RLHF 的原罪**：当年让 ChatGPT 一夜封神的 RLHF，教给模型的是「怎么回答能讨好人类」——**这套机制从第一天起就是为「辅助」而生的**，模型干的每件事最后都得有个人看一眼。他自己的比喻：

> 如果你的模型 95% 的时间像爱因斯坦一样聪明，但剩下的 5% 却表现得像憨豆先生，那么这种模型在自动化生产环境中根本毫无用处。

Jev 是他的答案：**把嘴缝上，只留判断**。

## 3. 开源同类产品：生态已经成型

先说结论：**Jev 本体闭源**（模型权重不公开、只有托管 API），但围绕它的开源生态**极其繁荣**——官方 SDK、Agent Skill、MCP server、以及大量可本地跑的同类模型，基本都是 MIT/Apache-2.0。

按「能不能自己跑」分成三类看。

### 3.1 开源权重：可以本地部署的同类模型

| 项目 | 规模 | 特点 |
|------|------|------|
| **Laya**（Convai Innovations） | 421M / 322M 多语言 | Apache-2.0，约 32k star，`pip install laya`，**服务器直接说 Jev 的 `/v1/systemone` 协议**，笔记本能跑 |
| **JevK5**（allebee） | Qwen3.5-4B | Apache-2.0，权重+代码全开放 |
| **Imajev-4B**（Mohit Garg） | Qwen3.5-4B LoRA | Apache-2.0，**JevBench 榜首** |
| **Plumb-4B**（crh225） | JevK5 v0.2 + LoRA | Apache-2.0，榜单第 2，**速度分 93.5 最高** |
| **decider-4b v2**（Mapika） | Qwen3.5-4B | Apache-2.0，**速度+成本双领先** |
| **Clef / Clef-Flash**（Cloudflare） | 27B / 9B | Apache-2.0，Qwen 微调，**API 声称完全兼容 Jev**，支持图文视频，Workers AI 上 $0.24/百万输入 |
| **pplx-decider**（Perplexity） | 27B | Apache-2.0，支持图像，官方 Decision Index 分数高于 Jev |
| **Open-Jev** | 2B / 9B / 27B | MIT 适配器 + Qwen LoRA，权重要另下 |
| **CLM-v0.1-8B** | 8B | Apache-2.0，`clm-serve` 实现 `/v1/systemone` |
| **Lichen / openjev-sglang / decider 35B-A3B** | 混合 | 分别走本地硬件、sglang、大参数路线 |

### 3.2 开源服务器：协议兼容，直接换 baseURL

这类最实用——**接 Jev 的代码不用改，只改 URL 和 key**：

- **jevos**（feder-cr/jev）—— MIT，**CPU 就能跑**，说 Jev 的 wire format，`choice`/`score`/`noul` 全支持
- **Laya server**—— 说同一套 `/v1/systemone` 格式
- **notjev**（9pings）—— JS 写的，模型无关，可接任何 OpenAI 兼容端点
- **deqio**—— 多引擎多硬件后端的统一 API
- **JevK5 serve / clm-serve / jevk5-serve**—— 各自模型的 serve 实现

> ⚠️ 一个诚实的提醒：**协议兼容 ≠ 能力对等**。社区项目的 README 写得很清楚——直接读出的概率是「给定选项上的归一化结果」，属于**偏好排序**，**并非校准过的置信度**。要替代 Jev，你得在自己的业务问题上重新验证。

### 3.3 开源工具链：把 Jev 接进 Agent

| 类别 | 项目 |
|------|------|
| **MCP server** | `typesafe-mcp`（System One Connector，单个 Go 二进制，一条命令注册到 Claude Code / Codex）、`jev-mcp`（codaaiteam，npx，5 个工具）、`JevMCP`（Python） |
| **Agent Skill** | 官方 `typesafe-ai` skill，一条命令装进 Claude Code / Codex |
| **SDK 适配器** | `system-one-adapter-python`——**同样的接口，但用普通 LLM 回答**，方便做 A/B 对照 |
| **实战项目** | `fast-jev-compaction`（上下文压缩）、Jev-as-a-Judge（LangChain 评测实验） |
| **评测/清单** | `JEVals`（独立评测 playground）、`awesome-jev-by-typesafe`、`awesome-system-one`、`awesome-jev-tools` |

### 3.4 独立榜单：开源已经在赢

**JevBench**（Benchmark Heaven 出品，与 TypeSafe 无关）v1.4.2.2 综合榜：

| 排名 | 系统 | 总分 | 智力 | 校准 | 速度 |
|------|------|------|------|------|------|
| 1 | Imajev-4B（开源） | 67.4 | 52.2 | 80.4 | 90.6 |
| 2 | Plumb-4B（开源） | 65.8 | 53.0 | 75.5 | 93.5 |
| 3 | decider-4b v2（开源） | 64.1 | 49.4 | 75.0 | 92.9 |
| **4** | **Jev 1.13.0（闭源 API）** | **63.3** | **53.1** | 76.3 | 83.3 |
| 5 | JevK5 v0.2.0（开源） | 62.0 | 48.9 | 74.5 | 91.1 |

**读这张表要注意三件事**：

1. **三个开源 4B 模型已经排在 Jev 前面**——而且是 4B 打 27B+ 的闭源托管服务
2. **Jev 的「智力」分仍是前十最高（53.1）**，校准分（76.3）也仍领先前三——**这两项是托管模型真正在卖的东西**
3. **开源模型赢在「速度」和「成本」**——而这两项恰好是自托管能直接改变的

榜单总计 95 个系统、91 个排名，2026 年 9 月底就已经这么卷了。

### 3.5 大厂入场：OpenAI 的 Decisions API

**发布仅三周后**，OpenAI 在 10 月 6 日推出 **Decisions API**，用现成的 **GPT-6 Luna**，不额外训练，靠限制返回结构化答案 + 系统优化，实现比通用 Responses API **快最多 10 倍**。

对比：

| | Jev | OpenAI Decisions API |
|---|---|---|
| 输入价 | $0.042/百万 token | $0.10/百万 token |
| 输出价 | 免费 | 免费 |
| 图像输入 | ❌ | ✅ |
| 训练 | 专门的 RLCD | 初版未额外训练 |

OpenAI 高管 Nikunj Handa 承认，Decisions API 此前四周并不在路线图上，是 Jev「激发了这一切」。但 TypeSafe 投资方 DCVC 的 James Hardiman 认为：**Jev 花了两年打磨的可靠性，才是隐形壁垒**——快速跟进的克隆产品在生产环境的表现未必能打。

## 4. 给开发者的实用建议

### 4.1 什么时候值得引入决策模型

判断标准很简单：**这个任务是不是「有限选项 + 高频 + 错了能恢复」**。

典型该用的：

- 工单路由、意图识别（每天几万次）
- 内容审核、风险分级
- 代码审查初筛、工具选择、任务是否完成的判断
- 上下文压缩策略（保留还是截断）
- Agent 的"裁判"角色（输出质量打分）

**典型不该用的**：需要多步数学推导的、需要生成长文本的、需要理解图像的。

### 4.2 接进去要注意的坑

1. **提问方式要改**——开发者 Aaron Roy 发现沿用传统 LLM 的提示方式会导致重要邮件漏标，**必须明确指定关键要素**（如金额、医疗关键词）
2. **要设置信度阈值**——高置信自动执行，低置信转人工，这是 Jev 概率输出的核心用法
3. **一次可以并行问多个问题**——检查一份文档时，写作质量和敏感词可以一起判断，不必逐项等待
4. **协议兼容不等于能力对等**——用开源替代品时，务必在**自己的业务问题**上重测校准度
5. **闭源/数据出网问题**——Jev 是托管服务，对数据不能出网的企业（以及中国大陆未开放地区）来说，**开源复现 + 本地部署才是现实路径**

### 4.3 一条务实的路线

```
先用 Jev API 验证价值（门槛最低，2 周能出结论）
  ↓ 确认某个环节真的省了钱
挑一个开源替代（Laya 笔记本能跑 / JevK5 需要 GPU）
  ↓ 迁移只改 baseURL
在自有问题上重测校准度，再决定是否上生产
```

## 5. 结论

Jev 火起来不是因为它"强"——它智力分只排第四，前面三个都是 4B 的开源模型。

**它火是因为它把一个一直被忽视的成本结构摊到了台面上**：AI 应用的账单里，大头不是"生成"，是"判断"。而判断这件事，用大模型做，等于用挖掘机挖花盆。

Diogo Almeida 的那句话概括了整件事：

> 我们花了七十年、烧了千亿美元，终于教会机器把话说得比人漂亮，然后发现自己造出来的东西，依然什么都不敢让它自己决定。

**大模型负责把话说漂亮，决策模型负责替它拿主意。** 这不是替代关系，是分工关系——Jev 的作者自己也是这么说的：**双核搭档**。

而开源社区已经用行动给出了答案：**三个月内，四个开源 4B 模型在综合榜上压过了闭源托管服务。** 协议兼容让迁移成本几乎为零，剩下的只是各自在业务问题上的校准功夫。

所以要不要用？我的建议是：**别追 Jev 这个产品，去追"决策模型"这个品类。** 前者的窗口期可能只有几个月，后者会重塑所有 Agent 的成本结构。
